# NewAPI 多功能插件（星涵煦版）

> `astrbot_plugin_newapi_tx` 是独立维护的 **New API 网站 × QQ 群联动插件**，为 [AstrBot](https://github.com/he0119/AstrBot) 打造，集用户绑定、额度经济、群聊娱乐、管理员工具于一体，并内置退群自动解绑与账号净化能力。

本仓库由 [Tianxu-Astrbot-Plugins](https://github.com/Tianxu-Astrbot-Plugins) 独立维护，功能与配置均以本仓库为准。

## ✨ 功能特性

- **双端身份绑定**：每个网站 ID 可**同时绑定一个 QQ 号（野机）与一个 OpenID（官机）**，两路身份通用——签到、打劫、抢红包、查余额任选一端触发均可识别。
- **野机优先**：同一用户在官机与野机同时触发签到时，官机侧自动让行约 1.5 秒，保证野机先完成签到、不重复领奖（可配置开关）。
- **经济系统**：每日签到随机发放额度（可翻倍、可衰减）、余额查询，额度显示精确到小数点后 6 位。
- **娱乐互动**：`打劫` 群聊玩法（支持 @ / QQ 号 / OpenID 目标）；`发红包` / `抢红包` 拼手气红包，微信式随机拆分、防重复领取、24 小时过期。
- **榜单**：余额榜 + 全站近 24 小时 token 消耗榜（消耗榜对所有用户开放）。
- **数据迁移**：管理员 `new-tx 导出` / `new-tx 导入` 一键导出/导入绑定与签到等核心数据（跨 MySQL / SQLite 均可）。
- **自动化管理**：监控指定群聊，成员退群（主动退群 / 被踢）时自动解绑并恢复网站用户组。
- **管理员工具**：远程查余额、解绑、智能查询、调整用户额度等便捷指令。
- **配置灵活**：优先推荐插件配置（WebUI）图形化设置，`.env` 文件作为备选，自动建表无需手动操作；另内置调试模式开关用于排查问题。
- **官机 Markdown**：来自官方机器人的回复自动按 QQ 原生 Markdown 发送（换行排版），野机保持纯文本；可开关控制。

## 🔧 安装步骤

1. **下载插件**：克隆或下载本仓库，您会得到一个名为 `astrbot_plugin_newapi_tx` 的文件夹。
2. **放置插件**：将整个 `astrbot_plugin_newapi_tx` 文件夹放入 AstrBot 实例的 `data/plugins/` 目录。
3. **重启服务**：重启 AstrBot，在 WebUI → `插件市场` → `已安装` 中即可看到本插件。

> ⚠️ 请勿同时安装本插件的多个副本/fork（如 `_fork`、`-fixed` 等重名目录），否则会出现消息被旧实例抢先处理等诡异现象；停用不如卸载干净。

## 📜 指令大全

> AstrBot 支持自定义唤醒前缀，下表指令**省略唤醒前缀**（无论你的前缀是 `/`、`#` 还是留空，直接加在指令前即可）。@ 目标也可直接写对方 QQ 号或 OpenID。

### 用户指令

| 指令 | 说明 |
| --- | --- |
| `绑定 [你的网站ID]` | 将您的身份与指定网站用户 ID 绑定。野机环境绑 QQ 号；官机环境需开启「OpenID 绑定」开关后绑 OpenID。同一网站 ID 可同时持有两种绑定 |
| `签到` | 每日签到随机获取额度（可触发翻倍）。QQ 绑定与 OpenID 绑定均可签到，同账号每日仅一次 |
| `查询余额` | 查询您当前绑定的网站账号剩余额度 |
| `打劫 @目标` | 对群内另一位已绑定用户发起打劫，有成有败；目标支持 @ / QQ 号 / OpenID |
| `抢红包 [红包代码]` | 抢指定代码的拼手气红包（字母数字随机码），回复附带抢的人昵称与 ID；全部抢完自动公布降序手气榜。可配置仅限官机（见下文红包章节） |
| `个人红包 [份数] [总额度]` | 用自己的余额发拼手气红包（扣款）：每满 5 余额可发 1 次/日，每日上限 10 次；首次发送前需 `验证令牌` 完成身份验证。开启「红包仅官机」时仅限官机触发 |
| `验证令牌 [网站访问令牌]` | 身份验证（个人红包 / 购买套餐共用）：校验访问令牌有效且与绑定网站 ID 对应，一次通过永久生效。建议私聊进行 |
| `行情 [币种]` | 查看模拟合约实时行情（真实交易所价格，含 24h 涨跌幅） |
| `开多 / 开空 [币种] [保证金] [杠杆] [止盈价] [止损价]` | 开逐仓多/空仓，最大亏损即该仓保证金；止盈止损可选，如 `开多 BTC 10 5` |
| `持仓` / `平仓 [仓位ID]` | 查看持仓浮盈 / 平仓（不带编号平掉全部） |
| `合约榜` | 今日模拟合约净盈亏排行 |
| `套餐` / `套餐列表` | 查看站点订阅套餐列表（只读：标题 / 价格 / 时长 / 额度 / 重置周期），并给出网站购买入口 |
| `购买套餐 [套餐ID]` | 用自己余额自助购买套餐（需站点支持订阅、管理员开启自助购买、且已完成 `验证令牌`） |
| `榜单` | 查看群内余额排行榜 |
| `消耗榜` | 展示全站近 24 小时 token 消耗排行榜（所有用户可用） |

| 指令 | 说明 |
| --- | --- |
| `发红包 [数量] [总额度]` | 发放拼手气红包（额度凭空发放、不扣款），如 `发红包 10 50`，公布 6 位随机代码。可配置仅限官机触发（见下文红包章节） |
| `查余额 [网站ID或QQ号/@对方]` | 查询指定用户网站余额（智能识别 ID，支持 @） |

| `查询 [网站ID或QQ号]` | 智能查询绑定关系（ID ↔ QQ 互查），存在 OpenID 绑定时一并展示 |
| `调整余额 [ID/@对方] [额度]` | 调整用户额度，正数增加、负数减少，如 `调整余额 12345 100` 或 `调整余额 @某人 -50` |
| `new-tx 导出` / `new-tx 导入` | 导出 / 导入核心数据表（绑定、OpenID 绑定、签到状态、打劫日志）到传输文件，跨数据库引擎迁移用 |
| `红包诊断` | 在对话内查看「红包仅官机」运行状态与最近 10 次红包指令的判定记录（时间 / 命令 / 触发者身份 / 拦截或放行），排查部署问题免翻日志 |
| `开通套餐 [@用户/QQ号/网站ID] [套餐ID]` | **直接开通套餐、不扣余额**（等价后台手动开通），回显套餐标题并回读确认订阅记录 |
| `查套餐 [@用户/网站ID]` | 查询指定用户的订阅记录（含历史：用量 / 到期 / 状态 / 来源） |
| `取消套餐 [订阅编号]` | 使指定订阅立即失效（编号见 `查套餐` 输出） |
| `pingapi` | 检查插件运行状态、数据库与 New API 连接状态 |

## 🔗 官机 OpenID 绑定与「野机优先」

群里同时存在野生机器人（NapCat 等，身份为 QQ 号）与官方机器人（身份为 OpenID）时：

1. 在 WebUI → **`核心绑定功能`** 中开启 **`是否支持官机 OpenID 格式绑定`**；
2. 用户在野机发 `绑定 [网站ID]` 绑 QQ 号，在官机发 `绑定 [网站ID]` 绑 OpenID——两路绑定互不冲突，可共存于同一网站 ID；
3. 之后无论从哪台机器人发起签到 / 打劫 / 抢红包 / 查询余额，都能正确识别为同一个网站账号；
4. 开启 **`野机优先`**（签到设置内，默认开）后，若同一条消息同时触达官机与野机，官机侧的签到请求自动让行约 1.5 秒，由野机先完成，避免并发竞态导致行为不确定。

另有两个可选绑定策略开关（WebUI → **`核心绑定功能`**，默认均关）：

- **仅野机绑定改分组**（`wild_bind_group_only`）：用户组晋升只由野机(QQ号)绑定触发；官机(OpenID) 绑定不改分组，绑定成功提示会注明。
- **官机绑定需先绑QQ**（`openid_require_qq_bound`）：网站 ID 必须先在野机完成 QQ 绑定，才允许在官机绑定 OpenID；未绑时官机会返回引导提示。

## 🧧 拼手气红包

- 管理员 `发红包 数量 总额度` 发出红包（凭空发放，无需扣款），机器人在群内公布红包**随机代码**；
- 用户 `抢红包 代码` 参与抢夺，抢到的回复会**附上抢的人昵称与 ID**，额度直接写入网站余额；
- 红包被全部抢完时，自动公布**手气排行榜**——金额从多到少列出所有领取者，超过 20 人只展示前 20；
- 微信式随机拆分，总额精确守恒；按红包加锁防止并发超抢，唯一记录约束防止同一用户多次领取；
- 有效期默认 24 小时，数量 / 总额度上限、有效期均可在 WebUI → **`红包设置`** 中调整；红包代码在过期并经过 **7 天冷却期**后可被新红包复用；
- **「红包仅官机」**（`official_only`，默认关）：开启后**所有红包指令（发红包、抢红包、个人红包等）只能经官方机器人触发**，野机收到的请求一律**静默忽略**——野机零回复、零消息量，避免刷屏触发风控；开启后发红包/个人红包公告会自动提示「仅可通过官方机器人抢夺」。

> ⚠️ 开启后野机仍能发红包/抢红包？不用翻日志——管理员发送 **`红包诊断`**：查看运行版本、开关状态、你的身份判定，以及最近红包指令的到达记录。**若刚发的指令没有出现在记录里，说明它根本没进到这份插件代码**（旧版本或重复副本在应答）；若有记录且显示「已拦截」，说明门控工作正常。另外请确认运行的是最新版而非早期拷贝（如 `_fork` 旧实例，无此门控）。

### 👛 个人红包（普通用户）

普通用户可以用自己的余额发红包（与管理员凭空发放的 `发红包` 互不影响）：

1. **身份验证（一次性）**：在 New API 网站「个人设置 → 生成系统访问令牌」，然后向机器人发送 `验证令牌 你的访问令牌`。插件会调用网站接口确认令牌有效且与你绑定的网站 ID 对应；通过后永久标记，之后无需再验。⚠️ 令牌等同密码，建议私聊机器人完成验证；
2. **发送**：`个人红包 [份数] [总额度]`——总额度从你的余额中扣除，不可超过当前余额；
3. **次数**：每满 5 余额可发 1 次/日（余额 10 可发 2 次，以此类推），每日上限 10 次；门槛与上限均可在 WebUI → **`红包设置`** 调整。当日资格随余额消耗实时收缩，跨天自动重置；
4. 抢夺规则与管理员红包完全一致：随机拆分、防超抢、防重复领取、过期作废；若建包时出现异常，扣款会自动全额退回；
5. 开启 **「红包仅官机」** 后，`个人红包` 同样仅能经官方机器人触发，野机收到的请求被静默忽略。

## 💾 数据库导入导出

用于更换数据库（MySQL ↔ SQLite 互迁）或备份：

1. 在旧环境执行 `new-tx 导出`，插件在数据目录生成 `transfer.db`；
2. 将该文件带到新环境的数据目录（`{AstrBot数据目录}/plugin_data/astrbot_plugin_newapi_tx/`）；
3. 执行 `new-tx 导入` 完成合并导入。

> 空的或不存在的 `transfer.db` 会被拒绝导入并给出提示；导入仅合并核心表（绑定、OpenID 绑定、签到状态、打劫日志），不影响其他数据。

## ⚙️ 核心配置

机密信息（数据库密码、API 密钥等）支持**两种配置方式**，可同时存在也可只配其一。

> **推荐使用插件配置（WebUI）**，图形化、无需手动维护文件；`.env` 作为备选方案，适合无法打开 WebUI 的场景。

> **优先级规则**：同一字段在插件配置与 `.env` 中同时存在时，**以插件配置为准**；只存在于一方时使用该方；两方皆空则初始化失败。

### 方式一（推荐）：通过插件配置（WebUI）

在 AstrBot 的 WebUI 插件界面中打开本插件配置面板，在 `New API 网站配置` 与 `数据库配置` 分组下填写对应字段即可。其余功能配置（签到奖励、打劫概率、红包规则、消息模板、监控群号等）均可在同一面板中图形化配置，无需改文件。

### 方式二（备选）：通过 `.env` 文件

如果无法进入 WebUI 或希望以文件方式管理机密信息，可在插件根目录（与 `main.py` 同级）创建 `.env`：

```dotenv
# --- 数据库配置 ---
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=your_database_user
DB_PASS=your_database_password
DB_NAME=your_database_name

# --- New API 网站配置 ---
# 您的 New API 网站地址，结尾不要带 /
API_BASE_URL=https://your-new-api-domain.com
# 您在 New API 后台生成的令牌
API_ACCESS_TOKEN=sk-xxxxxxxxxxxxxxxxxxxxxxxx
# 执行管理员操作时使用的用户ID (通常是 1)
API_ADMIN_USER_ID=1
```

> 插件启动时会自动创建所需数据表，无需手动建表。

### 🗄️ 单 SQLite 模式（可选）

不想维护 MySQL 的轻量用户，可在 WebUI → **`SQLite 模式`** 板块中开启 **`use_sqlite_mode`** 开关。开启后：

- 不再使用 MySQL，绑定与打劫日志等数据存储在插件目录的 SQLite 单文件数据库中（`{AstrBot数据目录}/plugin_data/astrbot_plugin_newapi_tx/newapi.db`），自动建表、零配置。
- MySQL 相关配置（主机/端口/用户/密码/库名及 `.env` 中的 `DB_*`）全部忽略。

> ⚠️ **注意**：SQLite 模式与 MySQL 模式是**两套独立数据**，切换模式不会自动迁移已有绑定数据；请使用 `new-tx 导出` / `new-tx 导入` 进行迁移。

### 🐞 调试模式

WebUI → **`调试设置`** 中开启 `enabled` 后，消耗榜等命令会在后台日志输出深度诊断信息（缓存原始值、兜底查询命中情况、渲染全文与实例指纹），用于排查「绑定存在但 QQ 号不显示」类问题；日常使用建议保持关闭以保持日志干净。

## 🤖 自动化功能

### 退群自动净化

在 WebUI 配置中填写需要监控的群号列表后，当成员**主动退群**或**被踢出群聊**时，插件自动：

1. 查询该成员是否已绑定网站 ID（QQ 绑定与 OpenID 绑定都会清理）；
2. 若已绑定，删除其全部绑定记录；
3. 通过 API 将其网站用户组恢复为预设的默认组；
4. 在群内发送净化完成通知。

## 🎯 群白名单（只监听配置群）

在 WebUI → **`群白名单（只监听配置群）`** 板块中：

1. 开启 `enabled` 开关；
2. 在 `group_list` 中填写允许响应的群号。

开启后，`签到`、`查询余额`、`打劫`、`发红包`、`抢红包`、`个人红包` 六条指令**仅**在列表内的群中响应；其余群聊与私聊中触发将被**静默忽略、不做任何回复**。其余指令（`绑定`、`验证令牌`、管理员指令、退群净化等）不受影响。

## 🧩 订阅套餐（需站点支持）

> 需站点为**支持订阅功能的新版 New API**；老版本这些接口不存在，插件会明确提示「当前 New API 站点不支持订阅套餐」并给出排查方向。总开关 `subscription_settings.enabled` 默认关闭。

### 查看套餐
`套餐`（或 `套餐列表`）列出站点**已启用**套餐：标题、价格、时长、额度、重置周期，并附带网站购买入口。
若列表为空，插件会提示两种可能：站点未配置套餐，或站点未确认「支付合规声明」（未确认时站点会**静默返回空列表**）。

**购买入口链接与内网地址保护**：入口链接取自配置项 `subscription_settings.public_url`（对外地址，如 `https://api.example.com`）。
- 留空时**只显示站内路径** `/console/subscription`，插件**不会**使用 `api_base_url` 拼接链接——避免把内网地址（如 `http://[fd7a:...]:10021`）暴露到群里；
- 配置值缺少 `http(s)://` 前缀时会降级为路径显示并记录警告日志。

### 管理员开通（不扣余额）
```
开通套餐 @某人 2
✅ 已为 @某人（网站ID 24）开通套餐 #2「月卡」。
用户分组将升级到 vip
🔎 已确认生效订阅：#101（生效中）
```
- 目标支持 `@提及 / QQ号 / 网站ID / OpenID`，与 `调整余额` 一致
- 回显套餐标题，避免开错；命中**已停用**套餐会附加告警（站点允许管理员开通停用套餐）
- 开通后**回读订阅列表确认**，避免「接口说成功但记录没出现」
- 同一网站账号的开通操作加锁串行，防止连点并发双开

### 用户自助购买（可选，默认关）
开启 `allow_user_purchase` 后，用户可用 `购买套餐 [套餐ID]` 自助完成：
1. 需先 `验证令牌`（证明自己拥有该网站账号），插件**全程不保存**用户访问令牌；
2. 插件用管理员令牌拼出一次购买：**先按站点口径扣款**（`ceil(价格 × QuotaPerUnit)`，`QuotaPerUnit` 取自站点匿名 `/api/status`，与站点计费同源），**再附加套餐**；
3. 按网站账号加锁，锁内二次校验余额，杜绝并发双花；**附加失败自动全额退款**并记录错误日志。

> ⚠️ **方案取舍**（请评估后开启）：该路径**不产生站点官方订单**，网站后台的订单/收入统计中看不到这笔（扣款在站点侧有操作审计）；同时它绕过站点的 `allow_balance_pay` 校验，插件用 `enforce_allow_balance_pay`（默认开）补齐。
>
> 另：`official_only` 开启后，套餐指令在野机（数字 QQ 身份）被静默忽略，避免野机刷指令。

### 与退群净化的配合
套餐可带 `upgrade_group`（开通即改写网站用户组），而退群净化会把用户组改回默认组——两者会互相踩踏。开启 `revoke_group_on_leave_skip_subscribed`（默认开）后，退群前先检查是否存在生效订阅，命中则**跳过改组**，避免抹掉套餐权益；站点接口不可用/失败时按「无订阅」处理，保持原有行为。

## 📉 模拟合约（逐仓多空 · 真实行情）

> 纯娱乐玩法，用**真实行情**模拟炒币，**不涉及任何真实交易**；总开关 `futures_settings.enabled` 默认关闭。

### 玩法
用余额做**逐仓**合约：开仓时扣「保证金 + 手续费」，仓位名义价值 = 保证金 × 杠杆（1~10x）。
**逐仓**意味着最大亏损就是你这一仓的保证金——亏光即**爆仓**，不会牵连余额其他部分。

| 指令 | 说明 |
| --- | --- |
| `行情 [币种]` | 实时价格（含 24h 涨跌幅与行情源）；不带币种则列出全部支持币种 |
| `开多 [币种] [保证金] [杠杆] [止盈价] [止损价]` | 开多仓，示例：`开多 BTC 10 5`（保证金 10、5x）、`开多 BTC 10 5 70000 60000`（带止盈止损） |
| `开空 [币种] [保证金] [杠杆] [止盈价] [止损价]` | 开空仓，参数同上 |
| `持仓` | 自己的持仓列表：入场价、现价、浮盈、收益率、强平价 |
| `平仓 [仓位ID]` | 平掉指定仓位；**不带编号则平掉自己全部仓位** |
| `合约榜` | 今日净盈亏排行（含交易笔数与强平次数） |

### 机制说明
- **强平价**：多单约 `入场价 × (1 - 1/杠杆 + 维持保证金率)`，空单反向；价格触及即爆仓，保证金归零；
- **止盈/止损**：开仓时可选挂单，后台轮询命中后自动平仓；
- **手续费**：按名义价值计，开仓与平仓各收一次（默认 0.05%，可配）；
- **行情源**：Binance → OKX → Gate 依次**降级尝试**（免 API Key）；**全部失败时跳过本轮结算**，绝不按陈旧价格强平；
- **后台轮询**：默认每 30 秒结算一次，爆仓/止盈/止损会**主动播报到开仓所在群**（需 AstrBot 支持主动推送）；
- **风控**：单用户持仓上限（默认 3）、单仓最低保证金、杠杆上限、余额校验。

### 配置（WebUI → `模拟合约`）
`enabled`（默认关）、`symbols`（默认 BTC/ETH/SOL/DOGE）、`max_leverage`（10）、`max_positions_per_user`（3）、`min_margin_display`（1）、`fee_rate`（0.0005）、`maintenance_margin_rate`（0.005）、`poll_interval_seconds`（30）、`price_sources`（binance/okx/gate）、`liquidation_broadcast`（开）。

> 💡 提醒：本玩法会真实增减用户网站余额（盈则入账、亏则扣除），建议先在群里小额度试玩再放开。

## 🖥 官机 Markdown 回复

QQ 官方机器人支持原生 Markdown 渲染。开启 **`官机回复使用Markdown`**（WebUI → `回复输出`，默认开）后：

- 来自官方机器人（OpenID 身份）的请求，插件回复按 QQ 原生 Markdown 发送，换行自动转换；
- 来自野机（QQ 号身份）的请求始终保持纯文本；
- 若你的官方机器人没有原生 Markdown 权限，AstrBot 框架会自动回退普通文本发送，无需担心乱码。
